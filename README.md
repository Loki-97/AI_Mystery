# AI Mystery Room

A full-stack detective game built to the requirements in `spec.md`. The React client is in `client/`; the Express/MongoDB API is in `server/`.

## Run locally

1. Install Node.js 20+ and MongoDB (local or Atlas).
2. Copy `server/.env.example` to `server/.env` and set `MONGODB_URI`, a long `JWT_SECRET`, and `GEMINI_API_KEY`.
3. From the project root, run `npm install`, then `npm run dev`.
4. Open `http://localhost:5173`.

The dashboard includes a sample fictional case so the investigation interface can be explored without generating a new case. New case generation requires a Gemini API key. Passwords and the answer key remain server-side.

## Deploy to Render

This repository includes `render.yaml`. Render builds the Vite client and serves it from the Express service, so the app and API share one origin. MongoDB Atlas stores the production data.

1. **Create a MongoDB Atlas database.** Create a project and cluster, add a database user with a strong password, and copy the Node.js connection string. Replace its username, password, and database name. If the password contains reserved URL characters, URL-encode them.
2. **Allow the Render service to reach Atlas.** In Atlas, open **Network Access** and add an IP access list entry. For Render plans without a fixed outbound IP, `0.0.0.0/0` may be needed; it allows connection attempts from any IP, so use a strong unique database password and least-privilege database user. If your Render plan provides fixed outbound IPs, allow only those instead. Atlas requires connections to come from an address on the project's IP access list ([Atlas docs](https://www.mongodb.com/docs/atlas/security/add-ip-address-to-list/)).
3. **Push this repository to GitHub** (or another Git provider connected to Render). Do not commit `.env` files or API keys.
4. **Create the Render service from the Blueprint.** In Render, choose **New → Blueprint**, connect the repository, and apply the `render.yaml` configuration. It sets the build command to `npm ci --include=dev && npm run build`, the start command to `npm start`, and `/health` as the health check ([Render Blueprint docs](https://render.com/docs/blueprint-spec)).
5. **Set the service secrets** when prompted or in **Dashboard → your service → Environment**:
   - `MONGODB_URI`: the Atlas connection string from step 1.
   - `GEMINI_API_KEY`: a key from [Google AI Studio](https://aistudio.google.com/apikey). Case generation will be unavailable without it; the sample case still works.
   - `JWT_SECRET` is generated by the Blueprint. Keep it private and stable; changing it signs out all users.
6. **Deploy and open the service URL** ending in `onrender.com`. Check `/health` on that URL; it should return `{"success":true,"data":{"status":"ok"}}`. Register an account and try the sample case, then try generating a case.
7. **For future updates**, push commits to the connected branch; Render deploys them automatically ([Render web service docs](https://render.com/docs/web-services)).

The frontend uses `/api/v1` by default, so no production `VITE_API_URL` or `CLIENT_URL` is needed for this single-service setup. If you host the frontend separately, build it with `VITE_API_URL` set to the API's full `/api/v1` URL and set the server's `CLIENT_URL` to the frontend origin.

## Architecture

- `client/`: React + Vite SPA.
- `server/`: Express REST API, Mongoose models, JWT auth, Gemini generation and validation.
- API prefix: `/api/v1`.
- Public case responses intentionally omit culprit and solution fields.

See `spec.md` for the product source of truth.
